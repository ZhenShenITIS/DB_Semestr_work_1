Что тут произошло и какие выводы можно сделать?

Запрос `SET enable_seqscan = off;` не отключает в PostgreSQL функцию использования последовательного чтения страницы. Цитата из документации PostgresPro (https://postgrespro.ru/docs/enterprise/13/runtime-config-query)
> enable_seqscan (boolean)
> Включает или отключает использование планировщиком планов последовательного сканирования. Полностью исключить последовательное сканирование невозможно, но при выключении этого параметра планировщик не будет использовать данный метод, если можно применить другие. По умолчанию этот параметр имеет значение on.

То есть семейство команд `enable... off` добавляет к стоимости выбранного метода константу, равную 10ккк

Если у таблицы нет никаких индексов, то планировщику ничего не остается как выбрать единственный метод сканирования, пусть и стоимостью 10ккк

Но такой подход действителен только до 17 версии Postgres, в 18 версии используется флаг `Disabled: true`

Цитата из статьи:
17 версия
```sql
                               QUERY PLAN                               
------------------------------------------------------------------------
 Seq Scan on t  (cost=10000000000.00..10000000035.50 rows=2550 width=4)
 Settings: enable_seqscan = 'off'
(2 rows)
```
18 версия
```sql
                     QUERY PLAN                      
-----------------------------------------------------
 Seq Scan on t  (cost=0.00..35.50 rows=2550 width=4)
   Disabled: true
 Settings: enable_seqscan = 'off'
(3 rows)
```

Информацию об этом и других изменениях в 18 версии можно прочесть тут - https://habr.com/ru/companies/postgrespro/articles/877752/#commit_e22253467
